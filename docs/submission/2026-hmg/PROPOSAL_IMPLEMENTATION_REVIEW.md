# SURPRIDE 기획서 본문 제안과 구현 대조

2026-11-11 · 코드 저장소 안에서 작성된 DOCX/PDF/PPTX/HWP 기획서 원본을 찾지 못했다. 상위 개인 폴더는 검색하지 않았다. 이 문서는 공식 접수양식 **02 작품 소개**에 옮겨 다듬을 개인정보 없는 제안 문구다. 참가자 정보·동의·서명 원본은 공개 저장소 밖에서 별도로 작성한다.

## 기획서 본문 제안

### 1. 앱 한 줄 소개

SURPRIDE는 오늘의 기분과 여유 시간으로 드라이브 코스를 고르고, 도착 순간에 목적지를 발견하는 Pleos Connect용 차량 앱입니다.

### 2. 기획 배경

쉬고 싶지만 어디로 갈지 정하지 못해 검색만 반복하는 순간에 주목했습니다. 사용자가 원하는 것은 항상 특정 장소가 아니라, 잠시 기분을 바꾸는 이동 경험일 수 있습니다. SURPRIDE는 목적지 검색보다 기분·시간·동행 조건을 먼저 묻고, 정해진 여유 안에서 새로운 장면을 발견하는 드라이브를 제안합니다. 이 문제와 수요는 아직 고객 검증이 필요한 제품 가설입니다.

### 3. 주요 기능과 차량 특화 요소

정차 상태에서 오늘의 기분과 시간, 원하는 풍경, 동행자와 왕복 여부를 설정합니다. 자연어로 쓴 조건은 구조화된 항목으로 바꾸고 사용자가 직접 확인·수정합니다. 경로와 목적지를 함께 평가해 시간 조건을 만족하는 코스를 준비하며, 준비 UI에서는 목적지 이름을 감춰 기대감을 유지합니다.

이 경험은 차량의 이동·정차 맥락과 결합됩니다. 운전 전 조건을 정하고 귀가 시간과 복귀를 고려하며, GPS·지도·길 안내로 이동 경험을 연결합니다. 조작 가능 상태와 내비게이션 소유권을 확인하고 불확실한 위치에서는 정확한 회전 안내를 계속하지 않는 방어 구조를 개발했습니다. 목적지를 감추기 위해 필요한 도로·안전 정보를 숨기지는 않습니다.

### 4. 주요 사용 시나리오

주말 오후, 짧게 기분을 바꾸고 싶은 사용자가 차량을 정차한 상태에서 “한강 느낌으로, 혼자 한 시간 정도 다녀오고 싶어”처럼 입력합니다. 앱이 정리한 조건을 확인하고 수정한 뒤 비밀 코스를 준비합니다. 제품 목표는 안내를 따라 이동하고 안전하게 도착을 확인한 뒤 목적지를 공개하고 만족도를 남기는 것입니다. 기록은 다음 드라이브를 떠올리고 최근 방문한 장소를 피하는 경험으로 이어집니다.

현재 정차 프로토타입에서는 입력·추천 준비·DEMO 공개·평가·기분별 개념 기록을 체험할 수 있습니다. 실제 도로 경로 API와 지도/GPS 안내 연동은 구현했으나, 현재 공식 Host 활성 안내·종료 조작의 최종 검증은 남아 있습니다. 소개 영상은 개별 검증 캡처를 편집한 것으로 실제 연속 주행 증거가 아닙니다.

### 5. 개발 계획

Kotlin Android 앱과 FastAPI 개발 프록시를 바탕으로 Pleos Connect의 Vehicle/NaviHelper 및 음성 SDK 연동을 진행했습니다. 차량 UX 제한과 정차 상태 확인, 카카오 경로 조회, OSM 지도, GPS 진행 판단, 자동 재탐색, 명시적 공개·평가·복귀·세션 복원 구조를 구현하고 회귀 검사를 보강했습니다. 현재 자연어 해석은 기기 내 규칙 기반이며 자유 대화형 LLM은 아닙니다.

12월 PT 전에는 공식 Host의 종료 접근과 소유권 정리를 우선 검증하고, 실제 사용할 서명 APK와 지원 환경의 실행 절차를 완성할 계획입니다. 음성 입력/청취 품질과 목적지 비공개 표면을 검증하고 실제 경관 후보를 확인합니다. 예선 시점의 정차 프로토타입을 실차·상용 서비스 완료로 표현하지 않습니다.

### 6. 기대효과와 발전 가능성

초기 타깃은 목적지를 미리 정하지 않은 짧은 주말 드라이브 이용자와 동승자입니다. 탐색 부담을 줄이고 시간 안에서 새로운 장소를 발견하도록 돕는 가치가 실제로 있는지 검증합니다. 초기 가설은 정차 체험 베타50명 모집과 목표 MAU50명, D7 재사용률30%입니다. **사업 계획상의 목표이며 관측된 사용자 수·유지율이 아닙니다.** 첫 조건 확정률·추천 만족도·다음 코스 요청률을 측정해 가설을 수정합니다.

검증 이후 지역별 확인된 코스와 장소를 확장하고 기분별 기록·재방문 경험을 발전시킵니다. 프리미엄 테마 코스나 지역 제휴는 검토할 수 있으나 현재 매출·계약·MAU 실적은 없습니다. 제휴 정보는 추천 신뢰도와 구분해 표시하는 방향을 검토합니다. 기록을 새로운 감정·정확한 경로 영구 수집 모델로 확대하지 않습니다.

### 7. 참고자료

검토한 [110초 편집본](assets/SURPRIDE_preliminary_prototype_110s.mp4)과 [구성·출처](DEMO_STORYBOARD.md)를 사용할 수 있습니다. 외부 영상 URL은 아직 없습니다. GitHub는 소스 열람과 공식 가산점 묶음의 준비도를 구분하고, 실행 가능한 Release가 없는 상태에서 완료된 APK 링크를 기재하지 않습니다. 공식 양식에는 실제 공개·접근 확인을 마친 링크만 사람이 옮겨 적습니다.

### 8. 숏폼

이번 작업에서는 숏폼 게시·링크 제출을 하지 않았습니다. 별도로 제작한다면 공식 특별상 조건을 다시 확인합니다.

## 평가 항목별 설득력

공식 필수 평가 항목은 차량특화성·창의성·기술 활용성·사업성이며 세부 배점은 공개되지 않았다. 아래는 SURPRIDE의 제안 논리이지 심사 점수 예측이 아니다. [공식 심사 기준](https://appdevchallenge.auto-hmg.io/guide/judging-awards).

| 항목 | 강조할 논리 | 근거와 보완 |
|---|---|---|
| 차량특화성 | 이동 자체를 짧은 휴식 경험으로 설계, 정차 입력·시간/복귀·소유권·음성/GPS 연결 | 실제 정차 UI/SDK 연결·계약 검사. 실차/정상 Host 종료 검증 필요 |
| 창의성 | 기분→조건→비밀 코스→도착 발견→기록으로 연결 | 단순 장소 목록보다 경험의 순서를 제안. 완전한 신규성/경쟁 우위 조사는 미실시 |
| 기술 활용성 | 차량 맥락·지도·실제 경로·안전 상태 전이 | 원자 저장·geometry·stale callback·watchdog 등은 개발 완성도 근거로 요약. 자유 대화 AI처럼 포장하지 않음 |
| 사업성 | 짧은 드라이브라는 구체적 이용 순간, 재추천/기록을 통한 재사용 가설 | 목표와 실측 분리. 인터뷰·베타·정량 지표와 제휴 검증 필요 |

## 구현 상태와 증거

정의: IMPLEMENTED는 명시된 코드/검증 범위에서 구현됨, PROTOTYPE은 플랫폼·경험 일부 검증, PLANNED는 향후 과제다. IMPLEMENTED도 Release/실차 인증을 뜻하지 않는다.

| 기능 | 상태 | 정확한 범위·근거 |
|---|---|---|
| 기분·시간·취향·동행·왕복·귀가 조건 | IMPLEMENTED | `ExperienceActivity`, core 모델/테스트, Phase5C 정차 UI 캡처 |
| 자연어 조건·일부 수정 | IMPLEMENTED | `RuleBasedMoodInterpreter`, MoodInputActivity·조건 계약. RULE_BASED이며 LLM 아님 |
| 경로·목적지 통합 점수 | IMPLEMENTED | `DriveExperienceEngine`, A07/A08 회귀. 시간·왕복·체류·출처를 평가 |
| 실제 장소·Kakao API | IMPLEMENTED | 서울 pilot5곳·개발 공개 출발지. Phase5C API 준비 기록, B4 계약 검사. 이번 API 재요청 없음 |
| 비밀 목적지 UX | PROTOTYPE | 준비 UI·목적지 없는 Trip. OSM 일반 POI/Host 등 시스템 전체 비공개는 PARTIAL |
| OSM/GPS/TBT/자동 재탐색 | PROTOTYPE | PoC 코드·B1/B3/B5 회귀와 과거 정차 관측. 현재 HOST_ACTIVE BLOCKED |
| 도착 확인·공개·평가·복귀·복원 | PROTOTYPE | B2/B5 저장·재생성 회귀와 과거 정차 화면. 전체 현재 Host 연속 실행은 미검증 |
| 기분 지도 | PROTOTYPE | DEMO 기분 개념도 UI. 실제 지리 지도·감정 변화 분석 아님 |
| LIVE 최근 방문 반영 | IMPLEMENTED | B4 완료·평가 증거 기반 candidate ID 정책. DEMO 기록과 분리, 실도로 방문 인증 아님 |
| STT/TTS | PROTOTYPE | SDK/제어/watcher 구현. STT PARTIAL, 실제 음향·최신 Host E2E 미검증 |
| 실제 경관도로·경유지 추천 | PLANNED | 실제 검증 경관 경유지 **0곳**. 후보/도로 검증 없이 LIVE 승격하지 않음 |
| 자유 대화 LLM·실지리 기분 지도 | PLANNED | 새 AI 학습·감정/GPS 영구 수집 구현 없음 |
| 실차·상용 서비스 | PLANNED | 제공업체/플랫폼 승인·보존 정책·운영 인증 필요 |

핵심 검증 문서는 `docs/phase6/B1_GUIDANCE_ACCURACY.md`부터 B6까지다. 최근 B6의 JVM/서버675 PASS와 이전 native31 이력을 인용한다. 이번 Phase6C 재실행 수치로 표시하지 않는다.

## 사용하지 않을 표현

“검증된 경관도로를 AI가 자유롭게 설계한다”, “목적지가 시스템 전체에서 완전히 숨겨진다”, “자유 대화 AI/STT 완성”, “실차 왕복 주행 검증 완료”, “상용 배포 준비 완료”는 현재 근거와 맞지 않는다. 대신 기획 가치→현재 구현 성과→PT 전 검증 계획 순서로 설명한다.
