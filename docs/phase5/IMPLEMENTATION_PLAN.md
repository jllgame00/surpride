## 3. 실행 명령과 회귀 관리

기존 스크립트/환경을 먼저 확인한 뒤 사용한다. 버전 업그레이드나 전역 캐시 변경을 디자인 작업에 섞지 않는다.

```powershell
.\scripts\build-codex.ps1 -Test
.\scripts\build-nav-host-poc.ps1 -Test
.\backend\.venv\Scripts\python.exe -m pytest backend/tests -q
git diff --check
```

추가 테스트는 실제 위험을 검증하는 경우에 한한다. 불필요하게 토큰 숫자 자체를 그대로 복제한 테스트를 늘리지 않는다. 상태별 presentation/비공개/안전 bounds/명시적 행동은 의미 있는 회귀 대상이다. 기존 테스트를 삭제하거나 통과용으로 약화하지 않는다.

단계마다 수정 파일·새 검증 결과·미검증 항목·전후 캡처를 기록한다. 전체 452개 회귀는 Phase 5B 시작/최종 기능 영향 검증 시 확인하고, 변경과 무관한 반복 빌드는 피한다. 실패한 경우 최초 원인과 후속 오류를 구별한다. UI 코드가 바뀌었다는 이유로 SDK/정책 판정을 올리지 않는다.

## 4. 승인 및 완료 gate

**구현 전 필요한 승인**은 디자인 방향 문서의 팔레트/경로 signature/진단 분리/지도 우선 구성이다. 이는 사용자의 “디자인 방향은 승인 전 확정 구현하지 않음” 제약을 따른다. Phase 5A 문서와 증거 작성에는 추가 승인이 필요하지 않다.

단계별 우선순위: 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8. 운행 제품 전환의 P0 위험은 4단계에서 우선 처리하며, 그 전에 기존 개발용 안내를 실차 사용 가능하다고 표기하지 않는다.

완료 조건: 승인된 방향, 기존 기능 보존, 앱 소유 UI 실제 캡처, 호스트 경계 준수, 기존 회귀 통과, 접근성/해상도 결과 기록. STT 최종 인식, 경관 데이터 확보, 시스템 전체 비공개, 실차 안전성은 UI 개선만으로 완료되지 않는다. 이들은 별도 후속 gate로 남긴다.
