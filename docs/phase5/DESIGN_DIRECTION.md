# SURPRIDE — 디자인 방향 제안

Phase 5A · 2026-11-09 · **사용자 검토용 제안, 아직 승인·구현되지 않음**

근거: [실제 화면 감사](UI_UX_AUDIT.md). 현재의 녹색/라임, `S /`, 경로 곡선, 한국어 슬로건을 출발점으로 삼는다. 새로운 지도 SDK, 유료 폰트, 사진, 웹 프레임워크는 필요하지 않다.

## 1. 제품에서 나온 방향

| 항목 | SURPRIDE의 정의 | 화면에 미치는 영향 |
|---|---|---|
| Product | 기분·취향·시간에 맞는 이동과 도착을 묶어, 목적지를 모르는 드라이브를 안전하게 준비한다 | 준비할 때는 조건과 총 시간, 달릴 때는 지도와 회전, 도착하면 장소와 이유를 우선한다 |
| Character | **차분한, 정확한, 호기심 있는** | 과장 없는 한국어, 분명한 상태·행동, 작은 발견의 요소. 감정을 진단하거나 경관을 지어내지 않는다 |
| World | 어두운 계기판의 명료함, 도로의 연속성, 여정 기록의 축적 | 짙은 녹색의 안정된 바탕, 라임의 한 가지 행동 강조, 실용적인 지도, 짧은 기록 |
| Moments | ① 비밀 코스 준비가 끝나는 순간 ② 정차 후 목적지 이름을 발견하는 순간 | 준비에는 열린 경로 모티프, 공개에는 장소명과 선정 이유를 집중 배치. 운행 중 브랜드 연출은 쉬어간다 |
| Signature | **끝을 남겨 둔 한 줄의 경로** | 기존 ExperienceArt 곡선을 정차 준비/공개/기록에만 반복. 준비에는 `?`, 공개에는 확인된 장소명. 실제 안내 경로·안전 정보는 이 장식 때문에 숨기지 않는다 |

방향 문장: **차분한 도로 위에서, 도착의 이름만 남겨 두는 인터페이스.**

경로 곡선의 끝을 열어 두는 표현은 브랜드용 개념도다. 실제 지도에서 차량 위치, 전방 경로, 필수 진출입·교차로·도로명을 지우는 원칙이 아니다. 일반 지도 라벨과 주변 풍경으로 장소를 추측할 수 있는 한계도 유지한다.

## 2. 핵심 화면의 시각적 약속

- 시작: 한 문장 소개와 하나의 “드라이브 준비” 행동. 기존 슬로건 “목적지는 몰라도, 가는 길은 즐겁게.” 유지. 개발 빌드에서 DEMO 체험은 분명히 구별한다.
- 조건: 한 단계의 선택과 현재 요약을 함께 보여 준다. 기분을 골랐는지, 다음 단계로 가는지 표현을 구별한다.
- 준비: 목적지 대신 총 이용시간·왕복 여부·준비물을 보여 준다. 코스 유형은 근거가 있을 때만 설명한다.
- 안내: 실제 지도와 현재 위치, 다음 회전·거리, 도로명, 남은 시간·거리를 우선한다. 비공개 상태는 작은 보조 문장이다.
- 공개: 장소명을 가장 먼저 읽고, 왜 골랐는지와 확인된 장소 정보를 읽는다. 평가·복귀는 그 다음이다.
- 기록: 지리 방문 인증이 아닌 기분별 기록이라는 의미를 명료하게 유지한다. DEMO와 AVD 기록은 시각적으로 구분한다.

## 3. 컬러 토큰 제안

우선 Dark를 기존 제품 팔레트에 맞춰 통일한다. Light는 같은 의미 체계의 **미검증 신규 제안**이다. 지도 타일·OEM·호스트 UI 전체 색상을 강제 변경한다는 뜻이 아니다.

| 토큰 / 용도 | Dark | Light |
|---|---|---|
| `color.background` | `#0A1818` 기존 유지 | `#F6F7F2` |
| `color.surface` | `#152827` 기존 유지 | `#FFFFFF` |
| `color.surfaceRaised` | `#203532` | `#EDF1E9` |
| `color.textPrimary` | `#EBF1E1` 기존 유지 | `#19231E` |
| `color.textSecondary` | `#9AB1A5` 기존 유지 | `#4B5C52` |
| `color.accentFill` | `#D7F28B` 기존 유지 | `#D7F28B` |
| `color.onAccent` | `#19231E` | `#19231E` |
| `color.accentText` | `#D7F28B` | `#3F5F27` |
| `color.divider` | `#2D4138` | `#D5DED3` |
| `color.focus` | `#EBF1E1` | `#24382F` |
| `color.successText` | `#B8DFB5` | `#285A35` |
| `color.warningText` | `#F2CF85` | `#78531A` |
| `color.errorText` | `#F3ABA3` | `#973D35` |

**라임은 주 행동과 중요한 진행 상태에 사용한다.** 선택값은 같은 라임 채움을 반복하기보다 체크·테두리·텍스트로 표시한다. 성공/주의/오류는 문구·아이콘을 반드시 동반한다. 색만으로 뜻을 전달하지 않는다. divider는 구획용이며 낮은 대비의 선을 필수 버튼 경계로 단독 사용하지 않는다.

### 계산으로 확인한 조합

불투명 sRGB 공식으로 계산했다. 실제 폰트, alpha, 안티앨리어싱, 지도·호스트 배경까지 검증한 결과는 아니다.

| 조합 | 대비 |
|---|---:|
| Dark 본문 / 배경 | 15.74:1 |
| Dark 보조 / Surface | 6.75:1 |
| Dark 라임 / 배경 | 14.66:1 |
| Light 본문 / 배경 | 15.00:1 |
| Light 보조 / 흰 Surface | 7.11:1 |
| Light 강조 텍스트 / 흰 Surface | 7.30:1 |
| onAccent / 라임 채움 | 13.04:1 |

라임 글자를 흰 바탕 위에 바로 쓰지 않는다. disabled alpha는 위 수치로 보장되지 않는다. 주의·오류·포커스·모든 상태 조합은 Phase 5B에서 추가 계산과 실화면 검토 후 채택한다. [Pleos 대비 기준](https://document.pleos.ai/en/docs/connect/guide/docs-design/Introduction/intro)을 충족하는 조합만 사용한다.

## 4. 글자·레이아웃·컴포넌트 토큰

아래는 **앱 소유 UI의 시작값**이다. 호스트 Routing 카드의 글꼴·크기를 지정하는 토큰이 아니다. Kotlin View는 dp/sp, Canvas는 Surface dpi와 글자 설정을 반영해 px로 변환한다. 실물에서의 물리적 크기 검증은 별도로 필요하다.

| 역할 | 크기 / 굵기 | 사용 |
|---|---|---|
| `type.brand` | 40sp / 600 | 정차 홈의 SURPRIDE |
| `type.display` | 36sp / 600 | 공개된 목적지, 정차 화면 핵심 제목 |
| `type.title` | 32sp / 600 | 페이지 제목 |
| `type.section` | 28sp / 500 | 조건 그룹/주요 소제목 |
| `type.body` | 24sp / 400 | 사용자에게 필요한 짧은 본문 |
| `type.action` | 24sp / 500 | 주요/보조 행동 |
| `type.supporting` | 20sp / 400 | 정차 보조 정보, 모드·데이터 한계 |
| `type.metric` | 32sp / 500 | 앱 ETA/남은 거리 |
| `type.diagnostic` | 18sp / 400 | 정차 개발 패널 전용, 주행 핵심 정보에 사용하지 않음 |

현재 14–22sp 설명을 모두 일괄 확대하면 2열이 넘칠 수 있다. 의미 없는 문구를 줄이고 창 높이를 재구성한 뒤 토큰을 적용한다. 한글 시스템 글꼴 `sans-serif`와 시스템 한글 fallback 유지. 새 폰트 다운로드 없음. 본문 줄 높이 약 1.35–1.5배에서 실제 한글/받침/큰 글자 검증. 긴 제목은 의미 단위 2줄까지, 정보 손실 없는 핵심 시간·오류는 잘라 버리지 않는다. 주행용 문구는 한 상태당 짧은 1–2줄을 목표로 한다.

| 항목 | 제안 값과 규칙 |
|---|---|
| 기본 grid | 4dp |
| 여백 scale | 4 / 8 / 12 / 16 / 24 / 32 / 48dp |
| 화면 inset | 기본32dp, 좁은 창24dp. Surface는 호스트 visible/stable bounds를 먼저 적용 |
| 그룹 간격 | 24dp, 그룹 내부12–16dp |
| 버튼 | 기본 최소 높이76dp, 강조88dp까지. 최소 터치76×76dp를 **프로젝트 목표**로 삼음. Pleos가 모든 경우76dp를 의무화했다고 주장하지 않음 |
| Primary | 화면/단계당 하나의 라임 채움, 의미 있는 동사. 파괴/취소 행동에 라임 채움 남용 금지 |
| Secondary | Surface 바탕+명확한 텍스트/경계, Primary와 같은 터치 크기 |
| 선택 컨트롤 | 체크/테두리/선택 상태, `selected/checked` 접근성 정보. CTA와 구별 |
| focus/pressed | 명료한 포커스 테두리와 눌림 상태. hover에만 의존하지 않음 |
| radius | 버튼12dp, 카드16dp, 큰 정차 패널20dp. badge/pill은 실제 상태에만 |
| border/shadow | 기본1dp 선, focus2dp. 장식용 그림자/glow 없음 |
| 아이콘 | 기본32dp, 핵심 회전 앱 아이콘48dp; 터치 영역은 별도76dp 이상 |
| 아이콘 스타일 | 기존 vector 확장, 단색의 일정한 굵기. Unicode 예시 회전은 정식 vector와 구별. 새 아이콘 SDK 불필요 |

기존 Native Button의 기본 inset까지 포함한 실제 터치/그림 영역을 측정한다. 숫자만 minHeight로 지정한 것을 실물 타깃 적합성 완료로 간주하지 않는다. 4mm/3mm 등 [Pleos 물리적 가독성 안내](https://document.pleos.ai/en/docs/connect/guide/docs-design/Introduction/intro)와 최종 차량 패널 확인이 필요하다.

## 5. 상태 피드백과 전환

| 상태 | 사용자 메시지 / 시각 처리 | 안전·동작 원칙 |
|---|---|---|
| 조건 해석 중 | “조건을 정리하고 있어요” + 단일 진행 표시 | 지연 시 처리 중임을 표시, 중복 요청 차단 |
| 미확정 조건 | “시간을 정해 주세요” 또는 “동행자는 아직 정하지 않았어요” | UNKNOWN을 추정으로 채우지 않음 |
| 코스 준비 | 총시간·왕복·준비물, “목적지는 아직 비밀입니다” | 장소 식별정보·허위 경관 문장 없음 |
| 재탐색 | “경로를 다시 찾고 있어요” | 신뢰 불가한 이전 회전 지시를 정상처럼 유지하지 않음. 호스트 loading 계약 유지 |
| 위치 저하 | “위치 확인 중” + 마지막 위치 신뢰도 | 정확한 안내를 확정하지 않음, 마지막 위치를 새 위치처럼 표시하지 않음 |
| 지도 실패 | “지도를 불러오지 못했어요” + 안전한 재시도 | 필요한 도로를 지운 채 정상 지도인 척하지 않음 |
| 연결 실패 | “경로 서버에 연결할 수 없어요” | LIVE 성공으로 바꾸지 않음. DEMO 전환은 명시적 선택 |
| 도착 후보 | “안전하게 정차한 뒤 도착을 확인해 주세요” | 정차 신호가 없으면 자동 도착/공개 확정 금지 |
| 공개 | 목적지명 → 이유 → 확인된 정보 | 즉시 공개와 도착 공개 제목을 구분 |
| 귀가 권고 | “복귀 시간을 확인해 주세요” + 추정 시간 | 시간 내 귀가 보장/자동 경로 전환 금지 |

정차 화면은 즉각적인 상태 갱신을 기본으로, 필요할 때만 120–180ms의 짧은 opacity 전환을 제안한다. 구현 우선순위는 마지막이다. 자동 반복·패럴랙스·문장 타이핑·화려한 공개 효과 없음. 주행 중은 지도/필수 안내 갱신만 유지하고 브랜드 애니메이션을 넣지 않는다. 시스템 모션 감소 설정과 생명주기를 존중한다.

## 6. 지도/호스트 적용 한계

- OSM 실제 도로·차량·방향·전방 경로를 유지한다. 라임 브랜드색으로 타일의 모든 길을 재색칠하지 않는다. 기존 경로선의 대비를 측정한 후 개선 여부를 결정한다.
- 최종 목적지명·주소·핀·Overview 종점은 공개 전 숨기되 일반 도로 라벨·안전 정보는 유지한다. 일반 라벨/주변 위치를 통한 추측 가능성은 남는다.
- OSM attribution과 출처 링크 정보를 계속 읽을 수 있게 배치한다. 하단 장식/상태 칩으로 덮지 않는다.
- host Routing 카드와 app footer의 정보 중복을 줄인다. native ETA를 쓰는 경우 host 재검증이 필요하며 기존 잘림을 앱이 임의 오버레이로 가리지 않는다.
- API 4에서 직접 Surface 버튼을 새로 구현하는 설계는 제외한다. 허용된 template action/정차 화면으로 공개·음성·복귀 조작을 제공할 수 있는지 실제 호스트에서 확인한다.
- 주야간 토큰은 앱 패널용이다. OEM/호스트가 결정하는 카드 색상, raster 지도 밤 표현, 실차 빛 반사는 별도 검증 대상이다.

## 7. 승인할 구체적인 결정

권장안은 다음 4가지다. 승인 전 코드에 적용하지 않는다.

1. **기존 짙은 녹색+라임을 공식 기본 팔레트로 유지**, Dark 우선 통일 후 Light 검증. 다른 색상 방향을 탐색하려면 이 단계에서 결정한다.
2. **S / 와 끝을 남긴 경로 곡선**을 브랜드 반복 요소로 채택. 준비·공개에서만 사용하고 주행 지도에는 장식을 추가하지 않는다.
3. **사용자용 정차 화면과 개발 진단 진입을 분리**하고, 제품 문구는 짧은 한국어로 통일. RULE_BASED/STT/모드의 사실 고지는 상세/적절한 보조 정보로 유지한다.
4. **지도·회전 우선의 간결한 안내**, 장소명 중심의 공개, 기분별 기록을 핵심 화면 질서로 채택. 호스트 UI는 공식 계약 안에서만 변경한다.

Light 실물색, 최종 launcher 아이콘, 선택 상태 모양, 조작 위치의 호스트 대응은 Phase 5B 화면 시안/실행 검토에서 확정한다. 현재 문서는 브랜드 방향 제안이며 앱마켓 승인이나 기능 완성 판정이 아니다.
